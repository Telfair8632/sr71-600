# Log 2026-11-19: IMU scale correction, PCB V1.1 arrival, and the V2 SMD board

Participants: me (bench work, measurements, decisions) + ZCode (firmware fix, documentation sync, board design).
This entry covers the two weeks after the E1 PCB order: the level-4 IMU correction, the arrival and electrical verification of the V1.1 board, and the decision to build a second, SMD version.

## 1. Documentation drift

The README and roadmap still said "level-4 firmware awaits hardware validation" and "board bring-up: milestone B in progress", while the bench had already moved past both. The status tables, `data/test_records.csv`, `firmware/README.md` and this roadmap now reflect the real state (2026-11-19).

## 2. Level-4 accelerometer scale correction

Measurement from 2026-10-13: at rest the accelerometer magnitude was **0.79–0.87 g** (expected 1.00 g). Since `|a|` is a physical invariant — it does not depend on attitude — a stable 0.80 g at every orientation means a **uniform scale error**, not a mounting or axis problem. Clone-chip tolerance, or residual damage from the earlier reverse-power incident.

Fix: a compile-time factor `ACCEL_SCALE_CORR = 1.25` (1/0.80) applied where counts are converted to g. Raw counts (`D,...` rows), gyro values, and the ratio-based pitch/roll are unaffected. The boot banner now prints `accel scale correction x1.250`, so a serial log identifies the build.

Rebuilt UF2: 71,168 → **71,680 bytes**. Only the `|a| ≈ 1.0 g` check needs to be repeated on hardware; the other six level-4 criteria already passed.

## 3. Level-6 firmware provenance

Before flashing `sr71fc_level6.uf2`, the firmware was rebuilt from the current source and the resulting UF2 compared with the checked-in file: **byte-identical SHA256** (`001FD8E4…68C0A`). The artifact really matches the source, and the build is reproducible.

## 4. PCB V1.1 arrived — and the board is two boards in one

The `SR71-600 main control board V1.1` board arrived bare. Continuity mapping (no power) first looked contradictory: the battery input did not connect to the 5 V capacitors or to U1's supply pin.

Explanation from the KiCad netlist: the board carries **both** the battery distribution and the flight-control logic, on **two separate ground nets**:

- `BATT_N` — J1.3, J2.2, J3.2, J4.2 (battery, both ESCs, UBEC input);
- `GND` — 34 pins (5 V capacitors, Pico sockets, U1.7, U2.3, Q1.E, all signal grounds).

They are joined **off-board**, through the UBEC (input − ↔ output −) and through the ESCs. Before the first power-up, `J4.2 ↔ J5.2` must read ~0 Ω; if not, the UBEC is isolated and a link wire is required.

Other findings: C1/C2's **round pad is positive** (the square pad sits on the negative side, opposite to the usual convention); the U2 footprint is a **1×5 SIP socket**, so the dual-row SOT-23-5 adapter purchased earlier will not plug in; the four 5.0 mm terminal blocks and the XT30 board connector are still missing. Bare board mass ≈ 30 g; assembled ≈ 60–70 g — a third of the aircraft's mass budget.

Details and the full pinout table: `docs/pcb_v1_1_wiring.md`.

## 5. Decision: a second, SMD board

Two problems with V1.1 cannot be fixed by better soldering: **mass** (60–70 g) and **assembly effort** (41 through-hole parts, ~150 joints). The V2 board therefore:

- moves the battery/ESC/UBEC distribution **off the board** (back to the original E1 philosophy: high current never enters the control board);
- keeps a single power entry at 5 V — an XT30, chosen for reverse-polarity safety — which is the only remaining hand-soldered joint (**2 pads**);
- converts everything else to SMD (0603 passives, SOIC-14, SOT-23-5, SOT-23, 2.54 mm SMD headers and sockets).

Result (2026-11-19): 65 × 85 mm, 1.0 mm, 1 oz, 37 SMD parts, 25 nets fully routed, 89 vias, **DRC 0 violations / 0 unconnected**, bare board ≈ 14 g, assembled ≈ 31 g. The electrical netlist is identical to E1 apart from the removed power section.

Details, files and ordering parameters: `docs/pcb_v2_smd_design.md` and `pcb/sr71_ctrl_v2/`.

## 7. Lessons

- **Documentation drift is hidden rework**: two status documents described a state that was already two weeks old. The fix is cheap, but only if noticed early.
- **A correction constant needs a provenance and an exit condition**: `1.25` is `1/0.80`, measured; a genuine GY-521 module must revert it to `1.0`. Both facts live in the source comment, not only in this log.
- **"Two grounds" is a design decision, not a fault** — but it must be verified externally (through the UBEC) before power-up, otherwise the logic reference floats.
- **Mass is a design constraint, not a post-processing step**: the V1.1 board was electrically correct and physically unbuildable within the budget.
