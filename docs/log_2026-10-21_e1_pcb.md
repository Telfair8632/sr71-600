# Log 2026-10-21: E1 Power-Distribution PCB — Designed, Verified, Ordered

Participants: me (decisions, DRC review, order placement) + ZCode (schematic/board generation, checks, release packaging). This entry covers the design sprint of 2026-10-20/21; the perfboard and firmware workstreams are summarized at the end.

## 1. Decision and Scope

While waiting for the remaining radio-system deliveries, I moved the E1 control and power circuit from perfboard to a printed circuit board. Split of roles:

- **Perfboard (milestone B, in progress)** stays the bring-up rig for debug levels 5–6 — it validates the circuit before the boards arrive.
- **PCB (`e1_power_dist_2s`)** is the v2 flight-intent board: the same E1 netlist, laid out for fabrication.

Scope decisions: motor leads and the MPU6050 module stay off-board (wired connectors); indicator LEDs for BAT+ and +5 V were added (each with a 4.7 k series resistor); R17/R18 (spare I2C pull-ups) are placed but marked do-not-populate; every part stays through-hole for hand soldering.

## 2. Design

Three-zone layout on a 74.68 × 94.56 mm, 2-layer, 1.6 mm, **2 oz** copper board with 41 through-hole parts:

1. **Propulsion power distribution** — XT30 input → dual ESC solder pads → UBEC input, sized for 18 A on 2 oz copper (BATT traces 3.0 mm).
2. **5 V zone** — C2 470 µF and C3 0.1 µF at the entry, plus the 5 V indicator LED.
3. **Logic zone** — Pico 2 socket headers, U1 (SN74AHCT125N) in a DIP-14 socket, U2 (SN74LVC1G17) on its SOT-23-5 adapter socket, Q1, the resistor group, and four test points.

Trace widths: BATT 3.0 / +5 V 1.5 / +3V3 0.8 / signal 0.4 mm. Ground is a double-sided pour stitched with 99 vias. 305 plated through-holes total.

## 3. Verification

- Schematic: ERC 0 errors; **27/27 nets matched** against the E1 topology document; footprint availability audited (U1 kept as true THT after an attribute fix; Q1 moved to KiCad's official TO-92 outline after the EasyEDA source showed 17 violations).
- Routing: **100/100 nets routed, DRC 0 violations, 0 unconnected** — report kept at `pcb/e1_power_dist_2s/kicad/drc_report_routed.json`.
- Release package (`release/20261021_000347`, mirrored in `pcb/e1_power_dist_2s/fab/`): 13 Gerbers + drill files, JLC-standard CPL (39 rows), assembly BOM aligned ref-for-ref with the CPL, procurement CSVs, and an order guide. **Two independent review rounds**: the first scored 8/10 and caught three real issues (CPL column naming, DNP filtering, BOM range notation); after fixes the package passes with the DNP residue re-verified clean.

## 4. Fabrication Order

Ordered **2026-10-21** on JLC (domestic site, www.jlc.com — the international site quoted an inflated ~USD 45 for the same job): 5 boards, 2-layer, 1.6 mm, 2 oz copper, lead-free HASL, green mask / white silkscreen, via covering, no SMT assembly — **about CNY 150–250**, delivery expected in 5–7 days.

One risk accepted at order time: Q1's pad clearance is 0.22 mm against the ~0.25 mm typical requirement for 2 oz copper; the fab may ask for a production confirmation.

## 5. Tooling Note

The board was produced with a Windows-adapted fork of the open-source PCB-Agent-Teams pipeline (schematic synthesis, rule checks, release packaging) driving KiCad 10.0.6. Getting that pipeline to run correctly on a zh-CN Windows machine — KiCad discovery, virtualenv paths, and a systematic UTF-8 encoding pass over 113 files so GBK locale decoding cannot corrupt UTF-8 schematics — is itself part of this project's engineering record; the patches are public at [Telfair8632/PCB-Agent-Teams](https://github.com/Telfair8632/PCB-Agent-Teams), branch `windows-patches`.

## 6. Erratum Fixed in the Documentation

The hardware check-in guide §5.4 listed the wrong pin order for U2 (SN74LVC1G17, SOT-23-5). Correct order per the datasheet: **1 = NC, 2 = A, 3 = GND, 4 = Y, 5 = VCC** (the guide had A/GND/Y/NC/VCC shifted by one pin). U2 is not soldered yet, so nothing was damaged; both the English guide in this repository and the Chinese original in the working folder are corrected as of today. **Before soldering U2, always verify against the physical datasheet.**
